# 棒球場地座標系與好球帶規格

> 來源：演算法團隊提供的打擊區 draw.io 規格圖（2026-07-27 修訂版）+ 口頭補充
> 用途：繪製九宮格、本壘板、打擊區、3D 軌跡的共用 domain 知識
> 單位：全文一律 **公分（cm）**
> 程式碼實作：[`app/components/baseball-field/core/fieldGeometry.ts`](../../app/components/baseball-field/core/fieldGeometry.ts)

---

## 1. 座標系定義

| 項目 | 定義 |
|---|---|
| 原點 `(0, 0, 0)` | **本壘板尖端**（指向捕手的那個角），位於地面 |
| `+X` | 一壘側（三壘側為負） |
| `+Y` | 投手方向（捕手方向為負） |
| `+Z` | 垂直向上（地面為 0） |

右手座標系。三個軸的用途分工很清楚：

- **X–Y 平面**（俯視）：本壘板、打擊區的場地幾何
- **X–Z 平面**（正視）：好球帶、九宮格、進壘落點
- **Y**：縱深，進壘點在本壘板側角平面（`Y = 21.59`）取值

---

## 2. 本壘板（Home Plate）

五邊形，尖端朝捕手。頂點座標（X, Y）：

```
(-21.59, 43.18) ┌─────────┐ (21.59, 43.18)   ← 前緣，面向投手
                │         │
(-21.59, 21.59) └─╮   ╭─┘ (21.59, 21.59)     ← 側角
                   ╲ ╱
                  (0, 0)                      ← 尖端，指向捕手 = 原點
```

| 尺寸 | 值 |
|---|---|
| 寬 | 43.18（X 從 −21.59 到 +21.59） |
| 總深 | 43.18（Y 從 0 到 43.18） |
| 側邊長 | 21.59（Y 從 0 到 21.59 是斜邊段） |

採 **MLB 官方 17 英吋 = 43.18 cm** 的精確值。

> **修訂紀錄**：早期版本曾把本壘板取整為 45 / 22.5，2026-07-27 的規格圖已改回官方精確值。連帶影響好球帶左右邊界與九宮格橫向格線（見 §4），舊值一律作廢。

## 3. 打擊區（Batter's Box）

左右各一個矩形，**不含**本壘板本身。

| | X 範圍 | Y 範圍 | 尺寸 | 站的人 |
|---|---|---|---|---|
| 三壘側 | −137.5 ~ −37.5 | −77.5 ~ +142.5 | 100 × 220 | **右打者** |
| 一壘側 | +37.5 ~ +137.5 | −77.5 ~ +142.5 | 100 × 220 | **左打者** |

關鍵尺寸：

- **間隙 15.91 cm**：本壘板側緣（±21.59）到打擊區內緣（±37.5）。官方規則為 6 英吋（15.24），規格圖上標示的「15」是概略值，實際以打擊區內緣 37.5 為準推得 15.91
- **前後不對稱**：以 `Y = 21.59`（本壘板側角那條線）為界，往投手方向 120.91、往捕手方向 99.09，合計 220

> **與官方規則的差異**：MLB 打擊區為 4 ft × 6 ft = 122 × 183 cm。本規格的 **100 × 220** 是自訂值。用於「畫面上呈現」沒問題；若要當成「有效偵測範圍」，使用前先向演算法確認（見 §11）。

## 4. 好球帶與九宮格

**左右邊界固定，上下邊界依打者身高計算。**

| 邊界 | 公式 |
|---|---|
| 左 / 右 | `X = ∓21.59`（即本壘板半寬，固定值） |
| 上緣 | `Z = 身高 × 0.535` |
| 下緣 | `Z = 身高 × 0.27` |

九宮格 = 這個框切 3×3：

- **橫向**：每格固定 **14.39 cm**（43.18 ÷ 3），格線在 `−21.59 / −7.20 / +7.20 / +21.59`
- **縱向**：每格 `(上緣 − 下緣) / 3`，**隨身高變動**

### 身高換算對照

| 身高 | 下緣 | 上緣 | 帶高 | 每格高 |
|---|---|---|---|---|
| 160 | 43.2 | 85.6 | 42.4 | 14.1 |
| 165 | 44.6 | 88.3 | 43.7 | 14.6 |
| 170 | 45.9 | 91.0 | 45.1 | 15.0 |
| 175 | 47.3 | 93.6 | 46.4 | 15.5 |
| 180 | 48.6 | 96.3 | 47.7 | 15.9 |
| 185 | 50.0 | 99.0 | 49.0 | 16.3 |
| 190 | 51.3 | 101.7 | 50.4 | 16.8 |

每格橫向**固定** 14.39，縱向隨身高在 11.9–16.8 之間變動（少棒到成棒的跨度，見 §5）。成人身高下接近正方形，但**九宮格不是正方形**，UI 不可假設格子等寬高。

### 好球判定：球心 vs 球緣

進壘點座標（`strike_zone_point`）是**球心**。兩種判定語意的邊界差一個球半徑 **3.65 cm**（球徑約 7.3 cm）：

| 語意 | 左右邊界 | 說明 |
|---|---|---|
| **球心**（本 repo 現行採用） | ±21.59 | 球心落在框內才算好球。判定框 = 顯示框 |
| 球緣觸及 | ±25.24 | 球的任何部分通過即好球，棒球規則的正式定義。判定框比顯示框大一圈 |

**現況：本 repo 兩個模組一律採球心**，與顯示的九宮格框一致。`isStrike()` 的 `byBallEdge` 參數保留切換能力，預設 `false`。

是否改採球緣屬產品決策，需與演算法端對齊（見 §11）——**顯示的九宮格框無論如何都畫 43.18 寬**，不隨判定語意改變。

## 5. 打者級別與代表身高

好球帶左右由本壘板寬固定、上下依打者身高計算，所以**「不同級別的好球帶」實際上就是「不同的代表身高」**——級別本身不改變任何幾何規則，只是決定 `getStrikeZone()` 要餵哪個身高。

### 取值方法

先算 **該級距內各年齡 PR50（均標）的算術平均**，再經教練校準定案。

- 取**平均**而非單一年齡：級距內各年齡的球員人數大致均等，只取最大年齡會讓低年級打者的好球帶整體偏高
- 取 **PR50** 而非 PR75：好球帶要對「典型打者」成立，不是對高個子
- **最終值經與業界教練討論後定案**：各級皆在 PR50 平均之上取整、幅度不超過 1 cm。代表身高不是算術平均的直接輸出，改 `pr50ByAge` 時不要順手把代表身高改回平均值

### 級別對照

| 級別 | 學制 | 年齡 | 各年齡 PR50（cm） | PR50 平均 | **代表身高（定案）** | 身高涵蓋範圍 |
|---|---|---|---|---|---|---|
| 少棒 | 小三–小六 | 8–11 | 126.8 / 131.8 / 136.5 / 142 | 134.3 | **135** | 117 – 156.1 |
| 青少棒 | 國一–國三 | 12–14 | 148.8 / 156.9 / 163.7 | 156.5 | **157** | 135.6 – 176 |
| 青棒 | 高一–高三 | 15–17 | 167.6 / 170 / 171.5 | 169.7 | **170** | 155.5 – 181.5 |
| 成棒 | 18 歲以上 | 18 | 172 | 172 | **172** | 161.5 – 182 |

「身高涵蓋範圍」= 最小年齡的 PR3（底標）到最大年齡的 PR97（頂標），供 UI 的身高輸入上下限用。相鄰級別的範圍會重疊，`inferLevelFromHeight()` 遇到重疊時回傳較小的級別。

### 好球帶換算

代入 `top = 身高 × 0.535`、`bottom = 身高 × 0.27`：

| 級別 | 代表身高 | 下緣 | 上緣 | 帶高 | 每格高 | 格子長寬比 |
|---|---|---|---|---|---|---|
| 少棒 | 135 | 36.45 | 72.23 | 35.78 | 11.93 | 0.83 |
| 青少棒 | 157 | 42.39 | 84.00 | 41.61 | 13.87 | 0.96 |
| 青棒 | 170 | 45.90 | 90.95 | 45.05 | 15.02 | 1.04 |
| 成棒 | 172 | 46.44 | 92.02 | 45.58 | 15.19 | 1.06 |

長寬比 = 每格高 ÷ 14.39（橫向格寬）。

### 三個實作要點

1. **本壘板不隨級別縮小。** 各級別都用同一塊 17 吋板，好球帶左右恆為 ±21.59。少棒的好球帶只有變矮，沒有變窄
2. **少棒的格子明顯偏扁**（長寬比 0.83，11.93 × 14.39）。九宮格的 UI 不能寫死正方形格子，否則少棒畫面會失真
3. **有實際打者身高時一律用實際身高。** 級別預設是身高缺漏時的 fallback，不是取代品

> 身高資料來源：新版 WHO 生長曲線圖 & 台灣兒科醫師研究團隊（男童身高）。女子組若要另立一套，需換用女童生長曲線重算——目前未涵蓋。

## 6. 視角與左右打

### 俯視圖方向

本壘在下、投手在上、一壘在右 —— 標準棒球場示意方向，等同**主審／捕手視角**往投手看。

### 正視圖（九宮格）方向

採**捕手視角**（站本壘後方看向投手），這也是 Statcast 等系統的業界慣例：

```
+X（一壘側）→ 畫面右
−X（三壘側）→ 畫面左
```

**不要**依打者慣用手翻轉畫面，捕手視角是固定的物理視角。

> ⚠️ 本 repo 的 2D 落點圖（`strike-zone-grid`）刻意**反轉 X 軸**（`toSvg` 中 `x = (xMax − px) × scale`），與後端 renderer 一致——世界座標 `+X` 畫在螢幕**左側**。這與上述業界慣例相反，是為了對齊後端輸出圖。改動前先確認後端行為。

### 內外角解讀

同一個 X 值對左右打者意義相反：

| X | 位置 | 右打者 | 左打者 |
|---|---|---|---|
| `> 0` | 一壘側 | **外角** | **內角** |
| `< 0` | 三壘側 | **內角** | **外角** |

若 UI 要顯示「內角高」「外角低」這類文字標籤，**必須**吃打者慣用手（`handedness`）才不會標反。純畫落點圓點則不受影響。

## 7. 程式實作

常數與計算集中在 [`app/components/baseball-field/core/fieldGeometry.ts`](../../app/components/baseball-field/core/fieldGeometry.ts)，全 repo 的單一來源。**不要在別處另抄一份數值。**

| 匯出 | 內容 |
|---|---|
| `HOME_PLATE` | `halfWidth` 21.59、`notchY` 21.59、`frontY` 43.18 |
| `HOME_PLATE_POINTS` | 五頂點 `(x, y)`，順序為 尖端 → 三壘側 → 前緣 → 一壘側 |
| `BATTERS_BOX` | `innerX` 37.5、`outerX` 137.5、`backY` −77.5、`frontY` 142.5、`gapToPlate` 15.91 |
| `ZONE_TOP_RATIO` / `ZONE_BOTTOM_RATIO` | 0.535 / 0.27 |
| `BALL_RADIUS` | 3.65 |
| `CM_PER_FOOT` | 30.48（`strike-zone-grid` 以英尺作業，換算集中在此） |
| `getStrikeZone(heightCm)` | → `{ left, right, bottom, top }`（cm） |
| `isStrike(x, z, zone, byBallEdge?)` | 好球判定，預設球心語意 |
| `getZoneCell(x, z, zone)` | → `{ col, row }`，0-based；`col` 0=三壘側、`row` 0=高；超界 clamp 到邊格 |

打者級別（§5）另放在同層的 [`batterLevels.ts`](../../app/components/baseball-field/core/batterLevels.ts)——資料來源不同（WHO 生長曲線，非場地規則），拆開才不會讓場地幾何跟著身高統計改版：

| 匯出 | 內容 |
|---|---|
| `BatterLevel` | `'little' \| 'junior' \| 'senior' \| 'adult'`（少棒／青少棒／青棒／成棒） |
| `BATTER_LEVELS` | 每級的 `label`、`grades`、`ages`、`pr50ByAge`、`referenceHeightCm`、`heightRangeCm` |
| `BATTER_LEVEL_ORDER` | 由小到大，可直接排 UI 選單 |
| `getStrikeZoneForLevel(level)` | → `StrikeZoneBounds`，等同 `getStrikeZone(該級代表身高)` |
| `inferLevelFromHeight(cm)` | 由身高反推級別，範圍重疊取較小級別，都不符回傳 `null` |

### 消費點

| 模組 | 用途 | 單位 |
|---|---|---|
| `app/components/pitch-trajectory/core/usePitch3d.ts` | 3D 軌跡圖的本壘板 mesh、九宮格角點 | cm（直接用） |
| `app/components/strike-zone-grid/core/useStrikeZoneScale.ts` | 2D 落點圖的好球帶縮放與九宮格 | 英尺（除以 `CM_PER_FOOT`） |

> `fieldGeometry.ts` 刻意放在 `app/components/` 下而非 `app/utils/`：後者會進 Nuxt auto-import，`isStrike` 這類泛用名稱會與各模組的同名 export 撞名。一律顯式 import。

## 8. 繪圖：俯視圖（本壘板 + 打擊區）

世界座標的 `+Y` 朝上，SVG 的 `y` 朝下，用 `scale(1, -1)` 翻轉後就能直接用世界座標畫。

```html
<!-- viewBox 剛好包住兩個打擊區：X −137.5~137.5、Y −77.5~142.5 -->
<svg viewBox="-137.5 -142.5 275 220">
  <g transform="scale(1, -1)">
    <!-- 三壘側打擊區（右打者） -->
    <rect x="-137.5" y="-77.5" width="100" height="220" fill="none" stroke="#888" />
    <!-- 一壘側打擊區（左打者） -->
    <rect x="37.5" y="-77.5" width="100" height="220" fill="none" stroke="#888" />
    <!-- 本壘板 -->
    <polygon points="0,0 -21.59,21.59 -21.59,43.18 21.59,43.18 21.59,21.59" fill="none" stroke="#fff" />
  </g>
</svg>
```

`viewBox` 的推導：`minX = −137.5`、`minY = −(最大 Y) = −142.5`、`width = 275`、`height = 220`。polygon 的點序等同 `HOME_PLATE_POINTS`。

⚠️ `scale(1, -1)` 會讓 `<text>` 上下顛倒。文字要放在翻轉的 `<g>` **外面**，自己換算位置，或在文字節點上再套一次 `scale(1, -1)`。

## 9. 繪圖：正視圖（九宮格 + 落點）

好球帶的實際尺寸隨身高變動，映射到固定的畫布方框比較好控版面：

```
u = (x − zone.left) / (zone.right − zone.left)
v = (zone.top − z) / (zone.top − zone.bottom)     // Z 越大 → SVG y 越小
```

本 repo 的實作是 `strike-zone-grid/core/useStrikeZoneScale.ts` 的 `createStrikeZoneScale()`，它多做兩件事：X/Y 共用同一縮放因子（球不會被壓扁）、外圍留 `paddingFraction` 邊距（預設 50%）讓界外球仍看得見。

落到好球帶外的球（例如高過上緣）算出來會超出方框，依需求決定：

- 保留超出位置，額外畫一圈「擴展區」背景，讓使用者看到偏多少
- 或 `clamp` 到畫布邊緣，並用不同顏色標示「壞球」

**不要**只做 clamp 而不做視覺區分，那樣所有壞球都會擠在邊框上、看不出差異。

## 10. 資料欄位對應

進壘點在 API 上是一個 3D 向量，拆成三個欄位：

| 欄位 | 3D 向量索引 | 對應軸 | 說明 |
|---|---|---|---|
| `strikeZonePointX` | `[0]` | X | 水平，一壘側為正 |
| `strikeZonePointY` | `[1]` | Y | 縱深，恆為 21.59（本壘板側角平面） |
| `strikeZonePointZ` | `[2]` | Z | 高度 |

畫九宮格用的是 **X（水平）× Z（高度）**，`Y` 不參與。

打者身高需另外從練習／打席層級的資料取得（例如 `batterHeight`），**沒有身高就算不出好球帶上下緣**。目前 bt3d 樣本不含身高，示範頁一律固定 175 cm；正式串接時要先決定身高缺漏的降級策略：用預設身高、或不畫好球帶框只畫落點。

## 11. 待向演算法確認

1. **好球判定用球心還是球緣**：座標是球心，規則上是球緣觸及即好球，兩者邊界差 3.65 cm（±21.59 vs ±25.24）。本 repo 目前採球心
2. **打擊區 100 × 220 的性質**：純顯示用，還是代表偵測有效範圍
3. **身高比例 0.535 / 0.27 的適用範圍**：這組比例源自成人資料，是否對少棒（8–11 歲）同樣成立？兒童的軀幹／腿長比例與成人不同，直接套用可能讓少棒好球帶偏低。若演算法端有分齡係數，`getStrikeZone()` 需改吃級別參數而非只吃身高
4. **是否需要女子組級別**：目前 §5 的級別表只用男童生長曲線，女子組要另立需換資料重算

## 12. 實作檢查清單

- [ ] 好球帶左右用 **±21.59**（MLB 17 吋本壘板半寬）；±25.24 是外擴一顆球半徑後的**球緣判定**值，不是顯示框
- [ ] 常數一律 import `fieldGeometry.ts`，不在模組內另抄字面值
- [ ] 好球帶上下用**身高比例**算，不可寫死常數
- [ ] 身高為 `null` 時的 fallback 已定義（建議用 §5 的級別代表身高，而非固定 175）
- [ ] 九宮格的格子**不假設正方形**——少棒長寬比僅 0.83
- [ ] 好球「判定」與「繪製」共用同一份邊界計算，避免兩處各自漂移
- [ ] 落在好球帶外的落點有明確視覺處理
- [ ] 內外角文字標籤（若有）依 `handedness` 判斷
- [ ] 俯視圖若用 `scale(1,-1)`，文字已另外處理
